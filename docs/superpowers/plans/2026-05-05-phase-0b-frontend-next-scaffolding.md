# Phase 0b — Frontend Next.js Scaffolding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the new `frontend-next/` app — Next.js 15 (App Router) + React 19 + TypeScript strict + Tailwind v4 + TanStack Query v5 + shadcn-style primitives — with a strict env layer, scoped theme isolation between `(web)`, `(auth)`, and `app/` route groups, empty placeholder pages, and a Dockerfile that runs alongside `backend-express` and `postgres` in the existing root `docker-compose.yml`.

**Architecture:** App Router with three theme-isolated route groups. Server Components by default; `'use client'` pushed as far down the tree as possible. CSS variables are declared per-scope via `[data-theme-scope="web"]` / `[data-theme-scope="app"]` selectors so the same shadcn primitives render with different visuals depending on which subtree wraps them. Two `api` flavors: `lib/api-client.ts` for the browser (cookies auto-sent) and `lib/api-server.ts` for Server Components (cookies forwarded via `cookies()`). TanStack Query is the only data layer in Client Components — never raw `fetch`. No business modules in this phase; auth, jobs, etc. land in later phases.

**Tech Stack:** Node 20+, TypeScript 5.6 (strict + bundler resolution), Next.js 15, React 19, Tailwind CSS v4, TanStack Query v5, Zod, Vitest, React Testing Library, jsdom, ESLint flat config, Prettier.

**Reference:** `docs/superpowers/specs/2026-04-26-nest-to-express-nuxt-to-next-migration-design.md` (sections 7, 8, 9), `docs/best-practices/nextjs.md`, `docs/best-practices/typescript.md`. The legacy `frontend/` (Nuxt 4) directory remains untouched on disk for reference until Phase 8 cleanup. Phase 0a (`backend-express/` scaffolding) is complete; the existing root `docker-compose.yml` already starts `postgres` + `backend-express` and will be extended (not replaced) by this phase.

  NEXT_PUBLIC_API_BASE: z.string().url(),
  NODE_ENV: z.enum(['development', 'test', 'production']).default('development'),

export function parseEnv(source: Record<string, string | undefined>): Env {
  const result = envSchema.safeParse(source)
  if (!result.success) {
    const issues = result.error.issues.map((i) => `${i.path.join('.')}: ${i.message}`).join('\n')
    throw new Error(`Invalid environment:\n${issues}`)
  }
  return result.data
}

export function getEnv(): Env {
  if (!_env) _env = parseEnv(process.env as Record<string, string | undefined>)
  return _env
}

const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? ''

export class ApiError extends Error {
  public readonly statusCode: number
  public readonly code: string
  public readonly details?: unknown

  constructor(statusCode: number, message: string, code: string, details?: unknown) {
    super(message)
    this.name = 'ApiError'
    this.statusCode = statusCode
    this.code = code
    if (details !== undefined) this.details = details
  }
}

interface SuccessEnvelope<T> {
  data: T
  meta?: unknown
}

interface ErrorEnvelope {
  statusCode: number
  message: string
  error: string
  details?: unknown
}

async function request<T>(
  method: string,
  path: string,
  body?: unknown,
  init?: RequestInit,
): Promise<T> {
  const url = path.startsWith('http') ? path : `${API_BASE}${path}`
  const headers: Record<string, string> = {
    Accept: 'application/json',
    ...((init?.headers as Record<string, string> | undefined) ?? {}),
  }
  if (body !== undefined) headers['Content-Type'] = 'application/json'

  const res = await fetch(url, {
    method,
    credentials: 'include',
    headers,
    body: body !== undefined ? JSON.stringify(body) : undefined,
    ...init,
  })

  const isJson = res.headers.get('content-type')?.includes('application/json') ?? false
  const payload = isJson ? ((await res.json()) as unknown) : null

  if (!res.ok) {
    if (payload && typeof payload === 'object' && 'message' in payload) {
      const err = payload as ErrorEnvelope
      throw new ApiError(err.statusCode ?? res.status, err.message, err.error ?? 'UNKNOWN', err.details)
    }
    throw new ApiError(res.status, res.statusText || 'Request failed', 'UNKNOWN')
  }

  if (payload && typeof payload === 'object' && 'data' in payload) {
    return (payload as SuccessEnvelope<T>).data
  }
  return payload as T
}

export const apiClient = {
  get: <T>(path: string, init?: RequestInit) => request<T>('GET', path, undefined, init),
  post: <T>(path: string, body?: unknown, init?: RequestInit) => request<T>('POST', path, body, init),
  patch: <T>(path: string, body?: unknown, init?: RequestInit) => request<T>('PATCH', path, body, init),
  put: <T>(path: string, body?: unknown, init?: RequestInit) => request<T>('PUT', path, body, init),
  delete: <T>(path: string, init?: RequestInit) => request<T>('DELETE', path, undefined, init),
}

import { cookies } from 'next/headers'
import { ApiError } from './api-client'

const API_BASE = process.env.NEXT_PUBLIC_API_BASE ?? 'http://localhost:3000'

interface SuccessEnvelope<T> {
  data: T
  meta?: unknown
}

interface ErrorEnvelope {
  statusCode: number
  message: string
  error: string
  details?: unknown
}

async function request<T>(
  method: string,
  path: string,
  body?: unknown,
  init?: RequestInit,
): Promise<T> {
  const cookieStore = await cookies()
  const cookieHeader = cookieStore
    .getAll()
    .map((c) => `${c.name}=${c.value}`)
    .join('; ')

  const headers: Record<string, string> = {
    Accept: 'application/json',
    ...((init?.headers as Record<string, string> | undefined) ?? {}),
  }
  if (cookieHeader) headers.Cookie = cookieHeader
  if (body !== undefined) headers['Content-Type'] = 'application/json'

  const url = path.startsWith('http') ? path : `${API_BASE}${path}`
  const res = await fetch(url, {
    method,
    headers,
    body: body !== undefined ? JSON.stringify(body) : undefined,
    cache: 'no-store',
    ...init,
  })

  const isJson = res.headers.get('content-type')?.includes('application/json') ?? false
  const payload = isJson ? ((await res.json()) as unknown) : null

  if (!res.ok) {
    if (payload && typeof payload === 'object' && 'message' in payload) {
      const err = payload as ErrorEnvelope
      throw new ApiError(err.statusCode ?? res.status, err.message, err.error ?? 'UNKNOWN', err.details)
    }
    throw new ApiError(res.status, res.statusText || 'Request failed', 'UNKNOWN')
  }

  if (payload && typeof payload === 'object' && 'data' in payload) {
    return (payload as SuccessEnvelope<T>).data
  }
  return payload as T
}

export const apiServer = {
  get: <T>(path: string, init?: RequestInit) => request<T>('GET', path, undefined, init),
  post: <T>(path: string, body?: unknown, init?: RequestInit) => request<T>('POST', path, body, init),
}

import { NextResponse, type NextRequest } from 'next/server'

export function middleware(req: NextRequest) {
  const accessToken = req.cookies.get('accessToken')?.value
  if (!accessToken) {
    const loginUrl = new URL('/login', req.url)
    return NextResponse.redirect(loginUrl)
  }
  return NextResponse.next()
}

export const config = {
  matcher: ['/app/:path*'],
}

## Notes for the Reviewer

- The plan deliberately produces empty stub pages — Phase 0b is scaffolding, not features. The first real form (LoginForm) lands in Phase 1 (Auth).
- `(auth)` shares `styles/app/theme.css` with `app/` per the spec's "Auth pages share tokens with app" rule. They differ only in shell component (`AuthShell` vs `AppShell`).
- The `Providers` component is a Client Component because TanStack Query requires it. It's mounted at the root layout so every Client Component below it (whether under `(web)`, `(auth)`, or `app/`) can call hooks like `useQuery`. There is no per-scope `QueryClient`.
- `middleware.ts` is intentionally minimal here — Phase 1 swaps the cookie-presence check for real JWT verification + refresh-token rotation.
- `next.config.ts` uses `output: 'standalone'` so the production Docker stage can copy a self-contained server bundle. This is unrelated to dev-mode behavior; `npm run dev` ignores `output`.
- The Dockerfile development stage uses `WATCHPACK_POLLING=true` so file watching works on bind-mounted volumes (same workaround as `CHOKIDAR_USEPOLLING` for the backend).
- Tailwind v4's `@theme inline` directive is the bridge that lets utility classes (`bg-primary`) resolve to scoped CSS variables. Without it, classes would resolve to whatever Tailwind's default theme provides.
- Standards enforced match `docs/best-practices/nextjs.md` (Server Components by default, push `'use client'` down, `cache: 'no-store'` for user data, RHF + Zod for forms, no `<img>`, no barrel files) and `docs/best-practices/typescript.md` (banned `any`/`!`/non-null assertions, strict tsconfig, `noUncheckedIndexedAccess`).
- No business modules are introduced — auth, jobs, dashboard, etc. all land in subsequent phases (1–7) where the layered hooks/server-action patterns get demonstrated in real use.
